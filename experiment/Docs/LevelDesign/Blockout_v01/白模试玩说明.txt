独立入口
地图：/Game/ReversedScale/Maps/L_NilinBlockoutV06
地图级 GameMode：/Script/experiment.NLBlockoutGameMode
角色：/Script/experiment.NLBlockoutCharacter
从工程根目录运行 Run_Blockout_Demo.cmd 进入独立桌面试玩；运行 Run_Blockout_Editor.cmd 打开独立地图编辑器。
DDC、着色器工作目录与启动日志保存在 Saved/BlockoutRuntime。启动器明确指定独立地图，不要求改变项目默认关卡。
最终场景以 +Y 上山、-Y 为主要构筑物正面方向；总览图画面右方对应 UE 世界 -X。LayoutSpec 的 world_mirrored_x=true 记录这一对应关系，平面图采用相同投影，不改变米制尺寸。

操作
WASD：移动；鼠标：转向。
Shift：加速，正常速度 500cm/s，加速 1400cm/s。
Space：跳跃。
F：切换步行/飞行；飞行时 Q 下降、E 上升。
数字 1–8：淡出后跳至对应节点；R：回到节点 01。
F1：重新显示操作提示。
左上导航 HUD 显示海拔、步行/飞行状态、最近节点及山顶方向/距离；不包含战斗血条或任务完成判定。低于 -120m 的坠落保护会安全返回节点01，仍需在真实试玩中复核。
数字跳点是开发评审工具，不是正式关卡的交互或通关条件。跳点读取 TargetPoint 的 NLBlockout.Node.01～08 标签，落点以地面坐标加胶囊半高和少量净空计算；保留原步行/飞行状态，阻塞时寻找安全位置，找不到则取消。

空间与美术意向
本轮依据“逆鳞_三关分区与丹炉归位_v06.png”创建基础体块：高门与守卫院、演武前院、开放炼丹亭与大炉、右侧持续登高桥阶、峰顶圆阵壁与石阙。
玩家站位 → 前方挚友/法阵 → 独立防守间距 → 后中轴巨炉 → 开放高檐亭，分别保留；炉体不放在挚友前方，也不侧移为小摆件。
峰顶使用石质封山圆环和悬剑代替重复的木构大殿。巨松、云海、山体与旗列目前均为白模体块，不是最终美术资产。
工程采用单张独立地图将建议高程与连续桥阶连接，节点间额外落台只用于行走和评审；这些过渡面不等于新增正式关卡或战斗场地。

本轮没有实现
没有接入正式敌人 AI、刷怪波次、守点计时、解救判定、Boss阶段、封山解锁、关末升级、存档或正式通关逻辑。人形仅为静态位置示意。独立漫游角色不加载现有剑盾、战斗 HUD、存档或训练敌人。
新增的近战干扰位、三角阵眼及胜利绕行标记也仅为布局占位，尚不执行伤害、破阵或出口解锁。
没有替代原训练关、VR验证图或原有角色；正式 VR 双手玩法与移动舒适性未在本白模验收。

剩余验证
1. 用户手动操作的飞行、升降、加速、跳跃、阻塞取消与坠落恢复体验；既定连续路线和八节点 PIE 落地已通过，不代表全键鼠按键均已人工实测。
2. 扩展到各院坪所有允许活动位置与不同眼高的峰顶/剑冠视线，不能只检查节点。院坪内部应保持的站位边界仍须随正式玩法确定。
3. 炉、挚友、阵眼与前向敌位的实机可读性，约28m战斗净空及约10mBoss距离是否适合正式玩法。
4. 最终真实截图的曝光、云海与边缘可读性；灰白云海体块不是最终体积云美术。
5. 实际帧率、静态网格数量与碰撞开销；必要时合并重复台阶/栏杆或用实例化降低开销。
6. 头显中的实际舒适性、坐/站眼高和双手信息优先级，仍须后续单独验证。

证据文件
Build.log：统一编译结果。
EditorProbe.json：本机 UE 5.8.2 Python API/基础资源探测。
LayoutSpec.json：地图生成器输出的布局记录，存在时仅作为生成参数依据。
MathCheck.json：纯 Python 几何尺寸与节点平面支撑复核；不等于 UE 碰撞、连续可达性或性能测试。
Validation.json：正常 Editor 的实际碰撞与离散视线检查，注意 checked_at 与具体覆盖范围。
RuntimeWalk.json：桌面 PIE 角色落地与连续路线运行记录；不等于 VR 正式流程或全部操作验收。
Plan/：从当前 LayoutSpec 动态生成的可编辑 SVG、PNG、交互 HTML 与源数据SHA记录；新版坐标方向为 -X 向图右、+Y 向图上。
