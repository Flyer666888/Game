本目录的 generate_plan.py 从上一级 LayoutSpec.json 动态生成白模平面图，不读取旧版概念图比例，不调用图像生成，也不启动 UE。

输入：LayoutSpec.json
支持四院矩形/圆形/不规则 polygon.points、过渡 rests、主构筑物 footprints、阶梯宽度与端点、八节点位置/yaw/高程、炉/挚友/Boss位置。
polygon.points 是世界 XY 米制坐标。world_mirrored_x=true 时，图面右方对应 UE 世界 -X，图面上方仍为 +Y；否则图面右方对应 +X。建筑正面示意朝 -Y；TargetPoint 箭头读取各节点真实 yaw 并应用相同投影，不改变原数据。

执行：使用项目可用的 Python 运行本目录 generate_plan.py。
可选参数：--spec 输入JSON绝对路径，--output 输出目录。
脚本通过本机已配置的 Node + sharp 渲染 PNG；Pillow 只用于缩小预览。

输出：
逆鳞_实际白模平面图_v01.svg：可编辑矢量总图。
逆鳞_实际白模平面图_v01.png：3600×2800展示图。
逆鳞_实际白模平面图_交互查看.html：本地交互查看器，支持缩放和建筑/推进/节点/位置图层切换。
preview.png：1800×1400预览。
PlanSource.json：源数据时间、SHA256、记录数量及缺失字段说明。

图面说明：
左侧总平面为统一米制比例；右侧四院放大图采用一致缩尺，以便比较院坪大小。建筑框线是投影占地，不等同于地面阻挡墙体。
金色线仅连接 LayoutSpec 中明确记录的阶梯端点，不虚构院内的实测行走路线。
底部高程条的纵轴来自节点 Z，横轴为节点顺序，不代表路线里程或可验证无遮挡的直线剖面。
炉/挚友/Boss圆标表示位置；除来源明确给出尺寸的footprint外，不将图标大小当作实体尺寸。

地图被重新生成后需重跑此工具。只有 PlanSource.json 的源数据SHA与当前 LayoutSpec 一致，才是该次生成对应的平面图。
碰撞、全程步行、终点可见性、曝光与性能的验证结果请看项目验收记录；本图本身不证明这些结果已通过。
