# 《逆鳞》AI 执行与任务模板

配套文档：[UE5.8 AI 开发方案](./UE5.8_AI开发方案.md)  
用途：交给 AI 编程助手执行具体开发任务。以下内容是提示词与任务卡模板，尚未在 UE 工程执行。

使用前将项目根路径、UE5.8 安装路径、AI 客户端及目标设备填实。先执行工程与连接核查，再执行玩法任务。

~~~text

主题：妖族龙子闯入炼丹宗门救出挚友。
三关：群体割草、守点解救、弹幕 Boss。

装备、数值和节点移动目前是原型工作方案。

工程根路径：<填写>
UE5.8 安装路径：<填写>
目标头显／手柄／OpenXR Runtime：<填写>
本轮任务：ENV-01，然后 AI-01。
资料位置：<填写两份开发文档的实际路径>

先读取适用项目说明、开发方案、已有源码与任务状态。
核对现有 .uproject、引擎版本、工具链和内容，沿用已有工程。
~~~

## 2. 项目约定模板

可由团队放入实际工程的协作说明文件。以下约定面向本项目的实现，不要求当前文档目录成为 UE 项目。

~~~text
项目：Nilin / 《逆鳞》
引擎：锁定的 Unreal Engine 5.8 补丁版本
目标：Windows PC VR，OpenXR，双手柄

实现原则：
- 核心规则 C++；蓝图负责资产与表现；Data Asset 负责调参。
- 伤害、格挡、反弹由统一结算器产生结果。
- 脚本不直接覆盖追踪相机俯仰与翻滚。
- 根节点移动不能被识别成主动挥砍。
- 战斗暂停期间停止伤害、冷却、波次、弹幕与解救进度。
- 实机验收与源码编译分别记录。
- 新反射声明使用完整编译和重启流程验证。
- 官方编辑器能力先复用，工具缺口再封装。
- 不直接编辑 .uasset/.umap 二进制。
- 修改同一编辑器资产时串行操作，保存后读回验证。
- 重试与超时操作先核对已有结果，避免重复对象。
- 接口变化同步更新契约与相关依赖。
- 碰撞速度 cm/s，距离 cm，时间秒。
- 一次任务提交源码、配置、资产清单和实际验证证据。

开发文件：
Docs/Architecture/Contracts.md
Docs/Architecture/AssetRegistry.md
Docs/AI/Capabilities.md
Docs/AI/State.md
Docs/Tasks/<TaskId>.md
~~~

## 4. 核心任务示例：近战

~~~text
任务 COMBAT-01：实现逆鳞刃有效挥砍。

前提：
VR Pawn 与主手追踪已可用；CombatContact/CombatResult 契约稳定。
读取方案第 7–9 节及对应源码。

目标：
一次有效横扫可以命中多个敌人，对同一敌人只伤害一次；
静止贴住或微小抖动不刷伤害；
节点自动转移不会造成挥砍。

实现：
- 在刀根、中段、刀尖采样并执行轨迹扫掠。
- 根据追踪空间的手部运动识别有效挥砍。
- 用 AttackInstanceId 和已命中目标集合去重。
- 转场、暂停恢复、追踪跳变时清空历史姿态。
- 阈值、采样半径和恢复时间可配置。
- 只提交命中候选，由统一结算器结算。

预期交付：
UNLBladeComponent 相关源码、原型刀与敌人测试资产、
Combat Lab 场景、轨迹调试显示、测试报告。

验证：
1. 一刀经过同一目标多次，只扣一次生命。
2. 一刀经过两个不同目标，两者均正确受伤。
3. 静止刀贴住敌人无持续扣血。
4. 快速与轻动作识别分别记录。
5. 自动转场与恢复追踪不会伤害敌人。
6. 实际头显挥砍漏判情况单独记录。

完成实际编译和可执行测试，并同步任务记录。
~~~

## 5. 核心任务示例：精准格挡

~~~text
任务 COMBAT-04：实现护心镜精准格挡与飞剑反弹。

前提：
普通屏障、护势、弹丸扫掠与统一结算器已通过。
读取方案第 7、10 节。

目标：
及时举镜获得精准窗口，反弹飞剑；
持续举盾不能重复开启精准窗口；
成功格挡后玩家身体不再被同一弹丸伤害。

实现：
- 初始窗口约 0.18 秒，采用统一战斗时间。
- 设置收盾再武装条件与最小重复间隔，参数可调。
- 普通格挡、精准格挡、破防返回明确结果。
- 反弹更新阵营、来源和合法目标。
- 清理旧伤害候选与碰撞忽略状态。
- 对象池复用清除上一代的攻击 ID 与反弹状态。
- 视觉、声音与震动订阅同一次 CombatResult。

验证：
1. 早举盾：普通格挡。
2. 合法窗口内举盾：精准反弹。
3. 持续举盾／阈值抖动：不刷精准窗口。
4. 屏障和身体同帧接触：玩家不额外扣血。
5. 暂停时窗口不消耗，恢复无错误反弹。
6. 反弹飞剑能伤害敌人或削弱 Boss 护阵。
7. 无合法目标时飞离并最终回收。
8. 复用同一弹丸不会保留旧阵营。

报告规则测试、场景测试与待实机项。
~~~

## 6. 关卡任务示例：守点

~~~text
任务 OBJ-01 / ENEMY-03 / LEVEL-02：
先实现法阵与干扰机制，再组装守点关卡。
三个任务分别交付，遵循依赖。

目标：
解救进度与法阵完整度独立；
破阵修士可暂停／减缓进度；
干扰来源消失后立即恢复；
完成、失败和重试互斥且无残留。

实现：
- 法阵作为独立受击目标，共用战斗结算。
- 干扰使用来源 ID 集合，支持多个来源。
- 明确同帧完整度归零与进度完成的结算顺序。
- 进度满后锁定状态、停止后续波次并处理规定余敌。
- 目标变化通过事件驱动 UI。
- 阶段检查点保存入口快照。
- 玩家无需持续按住交互。

验证：
两个干扰来源分别移除；
干扰源死亡、离场、重试后无残留；
暂停不增加进度；
完整度为零触发一次失败；
进度达标触发一次成功；
成功后旧波次不继续刷敌人。
最后用头显验证保护对象与优先攻击目标是否可读。
~~~

## 7. 关卡任务示例：Boss

~~~text
任务 BOSS-01：先实现飞剑、护阵与弱点的最小循环。

目标：
基础刃气可削弱护阵，精准反弹效率更高；
护阵破裂后弱点可受伤；
普通玩家也有可完成路径。

交付：
ANLBossCharacter、护阵/生命状态、
单组飞剑技能、反弹目标、输出窗口、测试地图。
先完成一轮循环，不同时制作所有弹幕。

下一项 BOSS-02：
增加数据化弹组与阵眼打断。
阵眼绑定到技能实例；击破后只取消对应技能。
取消时清理预警、待发弹组、计时器与目标。

验证：
- 普通刃气可推进 Boss。
- 飞剑反弹扣除正确护阵值。
- 弱点窗口之外不结算弱点生命伤害。
- 阵眼打断后旧技能不继续发射。
- 阶段切换、死亡与重试取消旧弹幕。
- 暂停恢复不一次性倾倒全部待发弹丸。

待上述通过，再交付 LEVEL-03 三阶段编排与结尾。
弹幕可读性和身体负荷必须记录实机结果。
~~~
